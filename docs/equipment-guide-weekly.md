# 장비 가이드 수집과 캐시

## 데이터 흐름

1. GitHub Actions가 매주 토요일 05:17 KST에 공식 랭킹의 직업별 깊이 10곳에서 각 20명씩 분산 조회합니다.
2. 주간 작업은 캐릭터의 OCID·직업·전투력만 서버 전용 Supabase 색인에 저장합니다. 장비 상세는 이 단계에서 조회하지 않습니다.
3. 사용자가 `비슷한 장비 검색`을 누르면 같은 직업 후보를 최대 90명까지 골라 최신 전투력과 현재 적용 장비를 함께 조회합니다. 공식 랭킹 API에는 전투력 범위 필터가 없어 서버 전용 색인을 사용합니다.
4. 목표 전투력의 ±15% 안에서 유효 캐릭터 30명을 채운 결과만 공개합니다. 저전투력 구간은 후보 부족을 줄이기 위해 최소 ±2,500만 범위를 사용합니다. 현재 적용 장비에 드롭률·메소 획득량 잠재가 있으면 해당 캐릭터를 제외합니다.
5. 유효 캐릭터 30명을 채우면 조회를 즉시 멈춥니다. 보통 약 80회, 드메 세팅이나 전투력 변동으로 탈락자가 많을 때 최대 200회의 Nexon API 요청을 사용합니다.
6. `직업 + 2,500만 전투력 구간` 결과를 7일 동안 공유하며 동시에 들어온 요청은 하나의 수집 작업만 실행합니다.

## 최초 설정

- Supabase SQL Editor에서 `supabase_create_equipment_guide_cache.sql`을 한 번 실행합니다.
- GitHub Actions Repository secrets에 `NEXON_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 등록합니다.
- `EQUIPMENT_GUIDE_MAX_REQUESTS` 변수는 기본 25,000회입니다.

## 장애 시 동작

- Supabase 캐시 테이블이 준비되지 않았거나 일시적으로 조회되지 않으면 기존 배포 스냅샷을 표시합니다.
- 장비 수집은 Route Handler의 응답 이후 실행되며 최대 실행 시간은 60초입니다. 화면은 2초 간격으로 완료 여부를 확인합니다.
- 2분 이상 멈춘 수집 잠금은 다음 요청이 다시 획득할 수 있습니다.
- 캐릭터 색인은 30일 안에 매주 교체합니다. 직업별 분산 수집으로 인기 직업 편향을 줄이며, 새 색인의 형식·날짜·표본 수·직업 수 검증이 실패하면 기존 색인을 유지합니다.

## 원본 응답 직접 확인

`npm run inspect:equipment-guide -- 캐릭터명 [YYYY-MM-DD]`을 실행하면 `.cache/equipment-guide-inspect/` 아래에 `id.json`, `stat.json`, `equipment.json`, `summary.json`을 저장합니다. API 키는 출력하거나 파일에 저장하지 않습니다.
